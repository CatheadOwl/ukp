UKP Remote quickstart

Goal: expose registered Services from one machine and consume them from another with the same endpoint commands: search, read, nav, rg, and propose when declared.

Current model:
- The ssh:// path needs nothing running on the host: each invocation wakes a loopback door over the SSH connection (it serves the host Registry fresh and self-reaps when idle). Host prerequisites: the host is ssh reachable and has ukp installed the usual way (npm i -g or bun add -g — the wake finds the standard locations; nvm users link ukp into /usr/local/bin once).
- The https path (LAN, public IP, or behind a reverse proxy) uses a resident door: run ukp serve under your process manager. Arbitrary consumers have no SSH credentials, so the listener itself is the trust boundary (TLS + bearer token).
- Prefer host door mode: run ukp serve without --endpoint to expose every local endpoint behind one port.
- The door reads the host Registry fresh on each request, so newly registered local endpoints appear without restarting the door.
- Declared endpoint names come from the host Service Manifest or discovery document; your registry binds each one under a local handle — the declared name by default, or --name <handle> when that name is already taken (two hosts both declaring 'notes' become your 'notes' and 'ali-notes'). --endpoint during register stays an expected-name assertion on the declared name.

Owner path over SSH (zero ceremony — nothing to start on the host):
1. Prerequisites (once): the host accepts your SSH key and has ukp installed the usual way
   ssh <host> ukp --help

2. On the consuming machine, import the door (the first call wakes it)
   ukp register --url ssh://<host>

3. Use the imported endpoints by name; later calls reuse the warmed connection
   ukp list
   ukp read --endpoint <name> notes/x.md
   ukp rg "keyword" --endpoint <name>

LAN HTTPS path:
1. On the host machine, run a tokened TLS door (keep it under your process manager)
   UKP_SERVE_TOKEN=<token> ukp serve --host 0.0.0.0 --tls
   Linux hosts can go resident-free too: systemd socket activation holds the
   port and spawns the door per use (ukp serve --systemd-socket, recipe in
   the deployment handbook)

2. On the consuming machine, import either the whole door or one endpoint
   ukp register --url https://<ip>:8570 --token <token>
   ukp register --url https://<ip>:8570 --endpoint <name> --token <token>

3. Use the imported endpoint normally
   ukp nav --endpoint <name>
   ukp read --endpoint <name> notes/x.md
   ukp rg "keyword" --endpoint <name>

Single endpoint mode:
Use this when you deliberately want to expose only one endpoint instead of the whole host Registry.
   UKP_SERVE_TOKEN=<token> ukp serve --endpoint <name> --host 0.0.0.0 --tls
   ukp register --url https://<ip>:8570 --endpoint <name> --token <token>

Name and identity:
- register --url fetches /.well-known/ukp.json and registers the declared name under a local handle (--name <handle> chooses another, e.g. when the name is taken).
- --endpoint <name> on register asserts the expected name; if discovery declares a different name, registration fails.
- A host door can import everything, --select a comma-separated subset, or --endpoint exactly one endpoint.
- Self-signed HTTPS certificates are pinned on first registration; compare the pinned fingerprint with the serve banner on untrusted networks.
- Non-loopback plain http is refused. Use https, ssh://, or loopback http for local testing.
- An ssh:// url port selects nothing: the woken door listens on a client-chosen loopback port.

Operational note:
- ssh:// hosts: nothing to manage — ukp wakes and reaps doors itself. To lock down what SSH may run, restrict the login shell (git-shell style); a forced authorized_keys command= does not compose with wake (the client chooses the door port per invocation).
- https hosts: keep ukp serve under your normal process manager, for example systemd, Task Scheduler, or a terminal multiplexer. The CLI does not install or autostart the door.
- serve accepts --max-idle <seconds> to self-exit after that long without requests (the same backstop the woken doors use).

Remember:
- Local registration makes a folder addressable on the host.
- Remote registration imports host-discovered endpoint bindings into the consumer Registry.
- Client Config still stores endpoint names only; after remote import, guide client works the same way as local endpoints.
