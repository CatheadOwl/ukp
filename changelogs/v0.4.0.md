# 0.4.0 - 2026-11-13

Upgrading at a glance: handing an endpoint to another machine collapses
into one gesture (`ukp serve status` self-describes the door, `ukp serve
share` mints the consumer's register command); consumer tokens default to
the OS credential store; a scoped key probing an out-of-scope endpoint now
gets an explicit route denial (still 404-shaped); the normative manifest
declaration reference ships in the package. Details below.

### Added

- `ukp serve --print-task` Notes gain an orphan-recovery recipe (field
  finding 2026-11-12): a scheduler End-Task strands the bun door process
  still holding the port while the freshly started launcher retries into
  EADDRINUSE — the note teaches killing the orphaned bun pid
  (`Get-CimInstance Name='bun.exe'` to list), after which the next
  retry in the 3x30s window binds by itself; the normal restart's
  `<wscript-pid>` anchor names the wrong process in this state (the live
  wscript is the new launcher). The regenerate note also now warns that
  a saved start-door.cmd can lag the live door (a widen that restarted
  without re-saving leaves the narrower --select on disk) — the live
  roster is the truth; flags the door cannot show are yours to re-supply.
- `ukp serve share` widen teaching points task-managed doors at the
  durable sequence — stop the door, re-save the print-task files with
  the wider --select, start the task — because a bare foreground rebuild
  leaves the saved cmd narrower and the next logon re-launches it.
- `ukp guide manifest full` reads the full normative manifest reference from
  the package (rendered verbatim from the bundled
  `skills/ukp/reference/manifest.md`): the cheat sheet's pointer to that
  package-internal path was unresolvable for a global install.
- Handing an endpoint to another machine collapses into one gesture:
  `ukp serve status` self-describes the door (live roster, which registered
  endpoints the roster hides, token summary, TLS identity pin, task vs
  manual deployment — no process introspection), and
  `ukp serve share <name> --to <label> --at <url> [--rw]` probes the door
  through the consumer-facing `--at` origin, validates the name against
  the live roster (teaching the `--select` rebuild command or
  `ukp register` first when it is not), mints a key scoped to exactly
  that name, and prints the consumer's paste-ready `ukp register` command
  with the raw key embedded (shown once — the token-add disclosure face;
  the door's `--select` width stays startup-fixed, widening still
  restarts).
- A scoped consumer now learns its own admission at register and list
  time: when the door's public document is fetched with a valid file key
  it additionally answers with that key's `admitted` names — the same
  roster a route denial prints — so `register --token` marks blind
  imports on the spot (`your key has no scope for it`) and `ukp list`
  marks unimported names and bindings outside the key. Anonymous,
  invalid, and env-token fetches keep the public document byte-identical.
- Consumer-side tokens now register into the OS credential store by
  default: Windows DPAPI (via the spawn-relay carrier), macOS Keychain,
  or Linux Secret Service — the registry keeps only a `token_ref` pointer
  and token resolution reads env > store > inline. When no store exists
  the register output says so loudly and the plaintext registry entry
  (with its `.bak`) remains the fallback; `ukp list --json` reports each
  remote binding's `token_residence`, and unregister removes the stored
  secret with its binding.
- The manifest declaration reference ships in the package:
  `skills/ukp/reference/manifest.md` is the normative grammar for
  `.ukp/service.toml` (every legal key, constraints, loadable examples),
  kept in lockstep with the loader's schema by an anchor test;
  `ukp guide manifest` routes there.
- `ukp guide propose` teaches the remote-submitter scope requirement (a
  read-only key has no propose route), and the README scopes row states
  the same ro/rw-to-propose mapping.
- The shipped agent skill face (`skills/ukp/SKILL.md`) gains a Remote
  section: consuming one is a single `ukp register --url <url> --token
  <key>`, sharing yours out is `ukp serve` with scoped keys.

### Changed

- **Behavior change** A scoped door key probing an endpoint it cannot
  touch now gets an explicit route denial — `no route for '<name>' under
  your key on this host door (available: <roster>)` — where 0.3.0
  answered exactly like an unknown name. The denial is still 404-shaped
  (never a 403) and uniform across a read-only scope, an absent scope,
  and an undeclared write route; names the door does not declare at all
  still answer byte-identically to unknown ones. The same boundary is
  visible before the first call through the register/list admission face
  (see Added). Behavior needs no migration; only scripts matching the
  0.3.0 message text should match the new denial line instead.

### Fixed

- A busy serve port now teaches the escape: when the chosen port is
  already taken, the startup failure appends `pass --port <n> (or --port
  0) to listen elsewhere` instead of failing without a remedy.
- rg spawn results classify by cause and name the executing side: a
  timed-out spawn (the win32 first-spawn Defender tax could exceed the 60s
  budget) previously printed `rg executable is not available` — it now
  fails as `rg timed out after Ns on this machine|the door host - retry the command once (a transient first call can succeed); if it keeps timing out, check rg on <side> or adjust UKP_RG_TIMEOUT_MS`, a missing
  binary reads `rg executable not found in PATH on <side>`, and other
  launch failures (EACCES, ...) report the errno code. Remote runs relay
  the door-side message verbatim, so the consumer learns which machine
  lacks the tool.
- `ukp serve status` scopes its down line to the address: `this address did
  not answer` + a custom-port same-value retry naming the 8570 default
  probe — a door started with `--port` is alive elsewhere and no longer
  reads as "no door on this machine".
- `ukp inspect` on a remote binding prints the registered url (the binding
  line previously leaked a literal `undefined`) and `status: local-only`
  pointing at `ukp list` — a by-design limitation is no longer labeled
  `status: failed` (exit code unchanged at 1). Field-confirmed 2026-11-13:
  a consumer machine on npm 0.3.0 quoted the old `failed: inspect deep-dive
  is local-only for remote endpoints` line verbatim — upgrading alone
  silences it.
- `ukp list`'s header parenthetical is local/remote neutral: `(built-in, no
  declaration needed)` replaces `(built-in, from the folder itself)`, which
  was false on a consumer machine where remote capabilities arrive from the
  door's discovery document.
- `ukp init --help` routes to `ukp init service --help` for the subcommand
  flags (`--name`, `--description`, `--dependency`) instead of omitting
  them — a replay reader concluded the flags the guide teaches did
  not exist.
- `ukp diagnose` on a remote binding prints `status: local-only` pointing at
  `ukp list` instead of `status: failed` (applicability, not health — the
  same vocabulary inspect carries; exit code stays 1, aligned with inspect),
  and `ukp list --help`'s `--json` line now states the text/JSON asymmetry:
  the text listing fresh-fetches each remote row's discovery document, JSON
  reads registry facts only. Field-confirmed 2026-11-13 on a consumer
  machine still quoting the 0.3.0 `failed:` wording.
- `ukp serve share`'s hidden-name widen teaching prints only the
  provably-correct delta — the wider `--select` set, merged into the door's
  own start command or saved task files with the owner's original
  `--host/--port` and TLS flags — and no longer assembles a full paste-ready
  rebuild line from the probe (a consumer-reachable probe origin is not the
  listen host; a blind paste silently narrowed a `--host 0.0.0.0` door to
  loopback). The task-managed durable sequence stays.
- Connection-level probe failures classify into human wording with the
  errno short code (refused / reset / timeout / resolve / TLS — each with
  its recovery direction), and the runtime's developer hints ("pass
  `verbose: true` in the second argument to fetch()") never surface. An
  origin that answers but is not a ukp door is its own status/share state —
  `something answered at <origin>, but it is not a ukp door` — never read
  as "the address did not answer".
- rg's timeout message teaches the retry first (`retry the command once — a
  transient first call can succeed`) before the UKP_RG_TIMEOUT_MS knob: the
  naturally observed first-call timeout recovered on an immediate retry. No
  startup warmup, no auto-retry — the root cause stays under investigation.
- `ukp serve share` on a repeated label states the resulting active-key
  count and the revoke scope (`token revoke <label>` removes EVERY key
  under the label — consumers holding an older key lose access too); the
  guide's cold-start recipe now arms the gate with a non-person label
  (`token add gate "notes:ro"`), so arming and per-person handovers no
  longer stack two active keys under one label.
- The guide's arming key teaches its full lifecycle: it is a bootstrap
  credential, not anyone's daily
  access — revoke it once per-person keys exist (re-minting on the door
  machine re-arms the gate anytime, so revoking costs nothing), and
  wanting your own remote access is just another handover (share to a
  label for your device). Mainstream backing:
  first credentials are never the owner's everyday credential across the
  surveyed systems (Vault/Jenkins/Rancher/K8s/Tailscale/GitLab et al.).
  The Scoped keys section's duplicate step numbering is fixed in passing.
- `ukp search` on an endpoint that declares no search capability teaches
  the lexical retreat at the failure point — the skip reason now ends
  `lexical search via 'ukp rg' needs no declaration` (rg is file-native,
  so the way out exists on every endpoint, local and remote alike).
  Field-proven wording (consumer machine, 2026-11-13: the user reached
  `ukp rg` only by prior knowledge).
- Manifest load failures split absent from unreadable: a folder with no
  `.ukp/service.toml` reads `no Service manifest in this folder (not a ukp
  Service): <path>` instead of the technically false `Service Manifest is
  not readable` (a present-but-unreadable manifest keeps that wording);
  consumers classify by error class (`ServiceManifestAbsentError`), and the
  door's 503 provider-unavailable bodies render the loader's message
  verbatim instead of nesting a second "not readable" prefix.
- `ukp list`'s door drift note works again for self-signed https doors:
  since 0.3.0 the check fetched the door's well-known document without
  the binding's TLS pin, so every self-signed https door rejected the
  fetch and the drift note silently disappeared for the remote line's
  primary deployment shape. The pin now rides with the fetch, exactly as
  the discovery document fetch already does.
- `ukp propose --file` read failures now state the path they resolved
  against (`resolved from the current directory: <path>`), so a relative
  path that does not exist is diagnosable at a glance.
- Unknown-endpoint and client-scope errors now carry their remedies
  (`ukp list` to inspect registrations, `ukp register --url <url>` to
  consume a remote endpoint, `ukp use` to edit the default set) instead
  of a bare endpoint name.
