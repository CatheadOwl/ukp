# 0.4.1 - 2026-11-14

Patch release carrying the eight findings of the 0.4.0 learnability
review, led by one security admission: a door bound beyond loopback on
plain http while holding bearer keys is now refused at startup. Scripts
keying on `ukp serve status` exit codes should read the Changed note
below.

### Security

- A plain-http door bound beyond loopback is refused at startup when it
  would hold bearer keys (an env token or any key in the tokens file) —
  previously such a door started with zero warning while its only
  possible callers (ukp clients refuse to register that url) would have
  sent the key unencrypted. The refusal teaches the four ways out: `--tls`
  (self-signed, pinned at registration), `--tls-cert/--tls-key`, a
  loopback bind behind a TLS-terminating proxy, or the explicit
  `--allow-http` for a door whose TLS is terminated in front of it (a
  reverse proxy on another host, a container sidecar) — an admitted
  `--allow-http` door prints a banner warning naming the plaintext hop
  and telling you to keep it on a private network. `--systemd-socket`
  rides the same rule because the listener's bind belongs to the socket
  unit. `ukp serve --print-task` mirrors the flag into the generated
  serve line, and the guide, README, and deployment guide state the
  refusal and the escape hatch at both ends.

### Changed

- `ukp serve status` exit code is now a health verdict: exit 0 only when
  the door is up; a down door, an answering non-ukp service, a door whose
  TLS cannot be anchored, and a single-endpoint door all exit 1 (aligned
  with `ukp inspect` / `ukp diagnose`). stdout stays the full report in
  every state — only the exit code changed, so a script chaining
  `ukp serve status && ukp serve share ...` no longer treats a dead door
  as healthy.

### Fixed

- The published package's `prepack` hook no longer breaks re-packing from
  an installed tree: the script it ran (the dev-side pack audit) does not
  ship in the tarball, so `npm pack` inside an install crashed with a
  module-not-found. The hook now runs the audit only when present
  (development checkouts — the enforcement is unchanged) and skips with a
  note otherwise.
- A dead binding (a registered endpoint whose folder was moved or deleted)
  can no longer be fingerprinted by authenticated callers: the route face
  and the door document now answer from ONE declaration set, so its name
  responds exactly like a never-registered one — as the guide's
  uniformity promise states. The startup banner also lists only the
  endpoints the door actually loads, instead of announcing one it then
  skips on stderr.
- `ukp serve status` on a host door that is up with zero endpoints no
  longer frames itself as "not answering": the door answered and its
  roster is simply empty — the report says so and points at registering
  endpoints.
- The launcher classifies spawn failures instead of blaming bun: leaving
  a shell inside a Service directory that was moved or renamed made the
  next ukp command report `no bun executable found` (bun was fine; the
  working directory was gone). The failure is now three ways — a missing
  working directory is named in the message (the operator can no longer
  see it themselves) with a change-directory remedy, a bun that vanished
  after the gate keeps the install-bun remedy, and other start failures
  report the errno code.
- `ukp serve status` splits the two causes of a registered endpoint being
  absent from the live roster: names the door was not `--select`ing keep
  the subset wording (a whitelist fixed at start), while a binding whose
  folder is unreadable or whose declared name drifted gets its own line
  naming the endpoint and the reason, with the re-register remedy — no
  longer read as a restart-resistant subset exclusion.
- Registering a single-endpoint door's url with a path segment no longer
  contradicts itself (`no such endpoint 'notes' ... it serves a single
  endpoint 'notes'`): the error now teaches the grammar — the `/name`
  path form addresses host doors only, register the root url and the
  served endpoint arrives under its own name.
- A scoped key's route denial on an empty effective roster no longer
  prints a bare `(available: )`: with a key in play it names the caller's
  own position (`your key grants no write routes on this door`), and an
  anonymous fetch on a door with zero endpoints gets `(the door serves no
  endpoints)`. The 404 shape and the two-tier uniformity are unchanged.
- `ukp list --json` gains an envelope-level `base_tools` report
  (`base_tools.rg`: `"ok"` or `"missing"`), so a missing ripgrep binary
  is visible to machine consumers — previously the row fields all read
  healthy while `ukp rg` was silently degraded. The rows themselves are
  unchanged (`base_tier` stays membership, not a liveness claim).
- Two terms gain inline definitions at first use: TOFU in the deployment
  guide (trust-on-first-use, what gets flagged when the identity later
  changes) and the README's `sidecar field` (the separate `ukp_uri`
  field carried next to the docid).
